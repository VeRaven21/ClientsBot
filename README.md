# ClientsBot

Telegram-бот для управления записями клиентов на услуги с системой уведомлений и администрированием.

## Описание

ClientsBot - это полнофункциональный бот для автоматизации записи клиентов на услуги. Бот поддерживает три типа пользователей: клиенты, сотрудники (мастера) и администраторы. Каждая роль имеет свой набор функций и интерфейс.

## Возможности

### Для клиентов
- 📅 Запись на услуги с выбором даты, времени и мастера
- 👀 Просмотр активных заказов
- 🔔 Автоматические напоминания за 2 часа до записи
- 🗑️ Удаление аккаунта

### Для сотрудников (мастеров)
- 📋 Просмотр своих заказов по датам
- 🔔 Уведомления о новых записях
- 📅 Навигация по календарю заказов

### Для администраторов
- 👥 Управление пользователями (просмотр статистики)
- 💼 Управление услугами (добавление, редактирование, удаление)
- 👷 Управление сотрудниками (добавление, удаление, просмотр заказов)
- 📊 Просмотр статистики заказов

## Технологии

- **Python 3.14** - основной язык программирования
- **aiogram 3.x** - фреймворк для работы с Telegram Bot API
- **SQLAlchemy 2.x** - ORM для работы с базой данных
- **PostgreSQL** - база данных
- **Docker & Docker Compose** - контейнеризация
- **uv** - менеджер зависимостей Python
- **Alembic** - миграции базы данных


## Установка и запуск

### Требования

- Docker
- Docker Compose
- Make (опционально, для удобства)

### Быстрый старт

1. Клонируйте репозиторий:
```bash
git clone https://github.com/yourusername/ClientsBot.git
cd ClientsBot
```

2. Создайте файл `.env` на основе `.env.example`:
```bash
cp .env.example .env
```

3. Заполните переменные окружения в `.env`:
```env
# Database
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
POSTGRES_DB=clientsbot
DATABASE_URL=postgresql+asyncpg://postgres:your_password@db:5432/clientsbot

# Bot
BOT_TOKEN=your_bot_token_here

# Admin IDs (comma separated)
ADMIN_IDS=123456789,987654321

# Working hours (24-hour format)
WORK_START_HOUR=9
WORK_END_HOUR=18

# Booking interval in minutes
BOOKING_INTERVAL_MINUTES=30
```

4. Запустите проект:
```bash
# С использованием Make
make up

# Или напрямую через Docker Compose
docker-compose up -d
```

5. Примените миграции базы данных:
```bash
# С использованием Make
make migrate

# Или напрямую
docker-compose exec bot uv run alembic -c /app/database/alembic.ini upgrade head
```

6. Проверьте логи:
```bash
docker-compose logs -f bot
```

### Команды Make

Проект включает Makefile для упрощения работы:

```bash
# Запустить контейнеры
make up

# Остановить контейнеры
make down

# Собрать образы
make build

# Пересобрать и перезапустить (полный перезапуск)
make rebuild

# Применить миграции
make migrate

# Создать новую миграцию
make migration name="описание_миграции"
```

### Остановка

```bash
make down
# или
docker-compose down
```

### Пересборка после изменений

```bash
make rebuild
# или
docker-compose down
docker-compose build
docker-compose up -d
```

## Конфигурация

### Переменные окружения

| Переменная | Описание | Обязательная | По умолчанию |
|------------|----------|--------------|--------------|
| `BOT_TOKEN` | Токен Telegram бота от @BotFather | Да | - |
| `ADMIN_IDS` | ID администраторов через запятую | Да | - |
| `POSTGRES_USER` | Имя пользователя PostgreSQL | Да | - |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL | Да | - |
| `POSTGRES_DB` | Название базы данных | Да | - |
| `DATABASE_URL` | URL подключения к базе данных | Да | - |
| `WORK_START_HOUR` | Начало рабочего дня (0-23) | Нет | 9 |
| `WORK_END_HOUR` | Конец рабочего дня (0-23) | Нет | 18 |
| `BOOKING_INTERVAL_MINUTES` | Интервал записи в минутах | Нет | 30 |

### Рабочее время

По умолчанию бот работает с записями в диапазоне **9:00 - 18:00**.

Для изменения отредактируйте переменные в `.env`:

```env
WORK_START_HOUR=10  # Начало в 10:00
WORK_END_HOUR=20    # Конец в 20:00
```

### Интервал записи

По умолчанию шаг записи - **30 минут**.

Для изменения отредактируйте переменную в `.env`:

```env
BOOKING_INTERVAL_MINUTES=15  # Интервал 15 минут
```

### Администраторы

Пользователи с ID из `ADMIN_IDS` автоматически получают роль администратора при первом запуске бота.

```env
ADMIN_IDS=123456789,987654321,555666777
```

## Использование

### Первый запуск

1. Отправьте боту команду `/start`
2. Пользователи с ID из `ADMIN_IDS` автоматически получат роль администратора
3. Остальные пользователи по умолчанию получают роль клиента

### Добавление услуг

1. Войдите как администратор
2. Выберите "Управление услугами"
3. Нажмите "Добавить услугу"
4. Введите название, цену и длительность

### Добавление сотрудников

1. Войдите как администратор
2. Выберите "Управление сотрудниками"
3. Нажмите "Добавить сотрудника"
4. Отправьте контакт или username пользователя (пользователь должен сначала запустить бота)

### Создание записи

1. Войдите как клиент
2. Выберите "Заказать услугу"
3. Выберите услугу из списка (с пагинацией)
4. Выберите дату (навигация стрелками ◀️ ▶️)
5. Подтвердите дату кнопкой ✅
6. Выберите время из доступных слотов
7. Выберите свободного мастера
8. Подтвердите запись

### Просмотр заказов

**Для клиентов:**
- Выберите "Мои заказы" для просмотра активных (будущих) записей

**Для сотрудников:**
- Выберите "Мои заказы" для просмотра заказов по датам
- Используйте навигацию для перехода между днями

## Система напоминаний

Бот автоматически отправляет напоминания клиентам за **2 часа** до записи.

Проверка выполняется каждые **10 минут** фоновой задачей в `scheduler.py`.

Для изменения интервала проверки отредактируйте `src/scheduler.py`:

```python
async def reminder_task(bot: Bot):
    while True:
        # ...
        await asyncio.sleep(600)  # 600 секунд = 10 минут
```

### Структура базы данных

Основные таблицы:
- `users` - пользователи (клиенты, сотрудники, администраторы)
  - `id` - UUID
  - `tg_id` - Telegram ID
  - `name` - имя пользователя
  - `username` - username в Telegram
  - `role` - роль (CLIENT, WORKER, ADMIN)
- `services` - услуги
  - `id` - UUID
  - `name` - название услуги
  - `price` - цена
  - `lenght` - длительность в минутах
- `orders` - заказы
  - `id` - UUID
  - `client_id` - ID клиента
  - `worker_id` - ID сотрудника
  - `service_id` - ID услуги
  - `start_time` - время начала

## Особенности реализации

### Проверка занятости мастеров

При выборе мастера система автоматически проверяет его занятость:
- Учитывается длительность услуги
- Проверяются пересечения с существующими заказами
- Мастер считается свободным, если его заказ заканчивается точно в момент начала нового

### Пагинация

- Услуги: 5 на страницу
- Сотрудники: 5 на страницу
- Навигация через кнопки ⏪ и ⏩

### Уведомления

- Мастер получает уведомление сразу при создании записи
- Клиент получает напоминание за 2 часа до записи
- Все уведомления отправляются автоматически

## Troubleshooting

### Бот не запускается

1. Проверьте правильность `BOT_TOKEN` в `.env`
2. Проверьте логи: `docker-compose logs bot`
3. Убедитесь, что база данных запущена: `docker-compose ps`

### Ошибки с базой данных

1. Примените миграции: `make migrate`
2. Проверьте `DATABASE_URL` в `.env`
3. Пересоздайте контейнеры: `make rebuild`

### Не приходят напоминания

1. Проверьте, что бот запущен
2. Убедитесь, что планировщик работает (проверьте логи)
3. Напоминания отправляются за 2 часа ±5 минут
